# M6.11 — Write-endpoint backlog remediation

**Parent:** [M6](./M6.md) · **Audit:** [`docs/audits/mutation-audit.md`](../audits/mutation-audit.md)

## Goal

Close the gap the M6.4 audit revealed: 127 mutation handlers across the UI touch local React state only. Wire every one to a server endpoint that validates, persists, audits, and surfaces side-effects (timeline events, status transitions, notifications) — using the pattern locked in by the incident-resolve demo slice.

## Pattern (locked)

Each write endpoint follows the same six-step pattern, established in the incident-resolve slice (M6.11 demo) and re-applied in changes/requests:

1. **Shared Zod schema** — `src/shared/schemas/<domain>.ts` (or extend existing). Both server route and client service import from there.
2. **Repo function** — single transaction: validate → snapshot → update + side-effect rows → return `{ before, after, internalId }`.
3. **Route** — `requirePermission('<key>.write')` (or `.resolve`/`.publish` for verbs already in catalog) → Zod parse → repo call → audit log → respond with updated snapshot.
4. **Service method** — typed against shared schema.
5. **UI rewire** — capture `refresh` from `useResource`; replace `setState`-only handler with optimistic local update → `await service.fn(...)` → `refresh()` (revert-on-failure for snappy modals).
6. **Vitest suite** — covers auth (401), validation (400), not-found (404), happy path (200), GET round-trip, side-effects (timeline / audit log), and 403 for caller missing the permission.

## Execution strategy

The backlog is ~40 endpoints across 7 domains. They're mostly independent — same pattern, different files. Subagent-driven (one implementer subagent per task + spec reviewer + code quality reviewer per task) is the right fit. Tasks below are batched so each is right-sized for a single implementer pass (one domain, one file family).
