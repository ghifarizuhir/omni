# M4 — Realtime + workers

**Status:** Scaffolded (no production load-test) · **See:** [BACKEND-MIGRATION-STRATEGY.md §M4](../BACKEND-MIGRATION-STRATEGY.md)

## What shipped

| Area | File | Notes |
|------|------|-------|
| Socket.IO gateway | `server/realtime.ts` | Authorizes upgrades via the session cookie. Path: `/api/v1/socket`. |
| Room scheme | `server/realtime.ts` | `tenant:${tenantId}:events`, `…:inbox`, `…:incident:${id}` |
| Emit helpers | `server/realtime.ts` | `emitEventCreated`, `emitEventUpdated`, `emitInbox`, `emitIncidentTimeline` |
| Job scheduler | `server/jobs/queue.ts` | In-process `setInterval` runner with a BullMQ-shaped API (`defineJob`, `startScheduler`) — swap-in to BullMQ on Redis is a 5-line change |
| Example job | `server/jobs/index.ts` | `sla-breach-detector` every 60s: marks `slaResolveStatus: 'breached'` on open incidents past their resolve target |
| Boot | `server/index.ts` | Creates HTTP server, attaches Socket.IO, starts scheduler unless `API_ONLY=true` |

## Subscription contract (client side, when wired)

```ts
const socket = io({ path: '/api/v1/socket', withCredentials: true });

socket.on('event:created', (e) => …);
socket.on('event:updated', (e) => …);
socket.on('inbox:item', (it) => …);

socket.emit('incident:subscribe', incidentId);
socket.on('incident:timeline', (entry) => …);
```

Clients **must reconcile against authoritative REST on reconnect** — don't treat the stream as the source of truth.

## Production migration path

1. Provision Redis.
2. Replace `server/jobs/queue.ts` with BullMQ imports — the `defineJob`/`startScheduler` surface is intentionally compatible.
3. Add `@socket.io/redis-adapter` to `realtime.ts` so multi-instance fan-out works.
4. Move job execution to a separate process (`API_ONLY=true` on the API node, a dedicated worker script that imports `server/jobs`).
5. Add SLA breach + capacity recompute + report generation jobs with cron expressions.

## Known limitations

- In-process scheduler means jobs die with the API. Fine for dev; not for prod.
- No ingestion endpoints yet (`POST /events/ingest` would feed the realtime fan-out).
- No reconnect/backoff strategy documented for clients — Socket.IO defaults are sane but should be tuned.
