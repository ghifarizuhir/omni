## Subscription contract (client side, when wired)

```ts
const socket = io({ path: '/api/v1/socket', withCredentials: true });

socket.on('event:created', (e) => …);
socket.on('event:updated', (e) => …);
socket.on('inbox:item', (it) => …);

socket.emit('incident:subscribe', incidentId);
socket.on('incident:timeline', (entry) => …);
```

Clients **must reconcile against authoritative REST on reconnect** — don't treat the stream as the source of truth.

## Production migration path

1. Provision Redis.
2. Replace `server/jobs/queue.ts` with BullMQ imports — the `defineJob`/`startScheduler` surface is intentionally compatible.
3. Add `@socket.io/redis-adapter` to `realtime.ts` so multi-instance fan-out works.
4. Move job execution to a separate process (`API_ONLY=true` on the API node, a dedicated worker script that imports `server/jobs`).
5. Add SLA breach + capacity recompute + report generation jobs with cron expressions.

## Known limitations

- No outbound webhook delivery worker yet — that needs the BullMQ swap to land first.
