# M3 — Domain coverage

**Status:** 🟡 Reads done · Writes deferred (re-scoped 2026-05-14 after M6.4 audit) · **See:** [BACKEND-MIGRATION-STRATEGY.md §M3](../BACKEND-MIGRATION-STRATEGY.md), [M6.md §M6.4 closeout](./M6.md)

> **Correction (2026-05-14):** This milestone was originally marked ✅ Done. The M6.4 mutation audit revealed that the M3 exit criterion *"Every UI action that should mutate state has a matching write endpoint, validated server-side"* was not actually met. Read endpoints exist for every domain (this is what shipped), but write endpoints exist for only 4 domains: auth, admin/roles, events/ingest, integrations. UI mutations on incidents, changes, requests, CMDB, monitoring rules, KB, problems, releases, and deployments all live in client-only React state. Tracked for remediation under **M6.11** in the [M6 tracker](./M6.md).

## Backlog closeout (2026-05-14)

The residual mock-backed domains moved to the DB via a generic **`Document`** table — one row per catalog/snapshot item, keyed by `(tenantId, kind, key)`. The `Document` model lives in `prisma/schema.prisma`; seeding is in `prisma/seedDocuments.ts`; reads go through `server/repositories/documents.ts`.

| Domain | Kind | Surface |
|--------|------|---------|
| Outages, SLA targets/breaches, daily health, availability series | `outage`, `sla-target`, `sla-breach`, `daily-health`, `availability-series` | `/api/v1/availability/*` |
| Capacity metrics/thresholds/forecasts/time-series/recs | `capacity-metric`, `capacity-threshold`, `capacity-forecast`, `capacity-time-series`, `scaling-rec` | `/api/v1/capacity/*` |
| Teams, notifications, inbox, on-call | `team`, `notification`, `notification-pref`, `quiet-hours`, `inbox-legacy`, `inbox-item`, `on-call-schedule`, `on-call-override` | `/api/v1/teams`, `/api/v1/notifications/*`, `/api/v1/inbox/*`, `/api/v1/on-call/*` |
| KB categories/feedback/analytics | `kb-category`, `kb-feedback`, `kb-analytics` | `/api/v1/kb/*` (articles already had their own table in M3) |
| Testing | `test-plan`, `test-case`, `test-run`, `sign-off` | `/api/v1/testing/*` |
| Status page, AI sessions | `status-page-entry`, `status-page-incident`, `ai-session` | `/api/v1/status-page/*`, `/api/v1/ai/*` |
| RBAC catalog | `rbac-user`, `rbac-team`, `rbac-application`, `rbac-department`, `rbac-division`, `rbac-role` | `/api/v1/rbac/*` |
| Continuity (DR, BIA) | `dr-plan`, `dr-run`, `bia` | `/api/v1/continuity/*` |
| Measurement (reports, ROI, dashboards, metrics) | `report`, `roi-calc`, `benefit-measurement`, `measurement-dashboard`, `metric-def` | `/api/v1/measurement/*` |
| Improvements + environments | `improvement`, `environment` | `/api/v1/improvements/*`, `/api/v1/environments` |

The `VITE_API_MODE` flag was **removed** along with `mockResult`/`mockRequired` from the client. `src/services/apiMode.ts` now just exports `API_BASE_URL`. Every service file was rewritten to call `apiFetch` directly. The frontend has no mock fallback anymore — the SPA always hits the API.

Trade-off documented: domains served via `Document` can't filter on inner JSON fields without parsing in JS, which is fine at current data volumes. When a `Document`-backed kind grows past ~10k rows or needs an index on a JSON field, promote it to a dedicated table (the route → repo seam means callers don't change).
