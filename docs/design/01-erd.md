## Design principles

1. **Tenant-scoped everything.** All operational rows carry `tenantId`. Query path always `requireAuth` → `withScopedDb` (`server/app.ts:126`, `server/middleware/scopedDb.ts:19`). Without it `tenantId=undefined` → Prisma emits no filter → cross-tenant leak. Never import `prisma` directly in routes (`eslint.config.js:19`), use `req.scoped.*`.
2. **Dedicated table where filtered, `Document` where small.** If UI filters/sorts on a field (`status`, `severity`, `priority`, `applicationId`, `scheduledStart`) the column is promoted + `@@index([tenantId, <field>])`. Small catalogs (outage, sla-target, ai-session…) stay in `Document(tenantId,kind,key)` and are only `list-by-kind` / `get-by-id` (`schema.prisma:582-601`).
3. **`String` JSON today, `jsonb` tomorrow.** Many `data: String` columns hold serialized JSON (`schema.prisma:6-10`). Repository must `JSON.stringify` on write / `JSON.parse` on read until `Json`+GIN migration lands. Do not query inside `data` JSON — promote field instead.
4. **Migrations squashed, append-only.** `prisma/migrations/0001_init_postgres` is the baseline (`01-erd.md:14`). New changes → `prisma migrate dev --name <snake>` then `npx prisma generate`. Never hand-edit SQL baseline.
5. **`publicId` is the external key.** Detail routes/logic expose `publicId` (human-typed, stable), `id` is internal PK. Most M3 tables (`Problem`, `Change`, `Release`, `Deployment`, `ServiceRequest`, `KBArticle`, `Event`, `MonitoringRule`, `AlertRoute`, `Incident`, `ConfigurationItem.publicId`) keep both (`schema.prisma:349-381`, `408-420`, `468-496`).
6. **PK strategy is mixed, intentional.** `cuid()` autogenerated for identity/doc/audit (`Tenant.id:24`, `Document.id:589`, `AuditLog.id:606`), explicit `@id String` (seed-mirrored) for CMDB/monitoring/incidents/M3 (`ConfigurationItem.id:278`, `Event.id:350`, `Incident.id:409`) — seed can re-play deterministic ids.
7. **RBAC is flat `Role → Permission`.** `Permission.key` is dotted `cmdb.write` (`schema.prisma:87`). `Role.tenantId=null` → system role (`isSystem=true:98` protected from edit/delete). Assignment via `MembershipRole(membershipId,roleId)` and `RolePermission(roleId,permissionKey)` (`schema.prisma:108-126`). Hierarchy `Division→Department→Team→Application` is org, not RBAC.

## Domain map

```
IDENTITY   Tenant, User (+self manager), TenantMembership, Session, ApiToken, NotificationChannel
RBAC       Permission, Role, RolePermission, MembershipRole
ORG        Division → Department → Team → Application ↔ ApplicationTeam (role OWNER|CONTRIBUTOR|VIEWER)
           FunctionalRole ↔ UserFunctionalRole

MONITORING Event, MonitoringRule, AlertRoute
INCIDENTS  Incident, IncidentComment, IncidentTimelineEvent

           ServiceRequest+RequestComment, CatalogItem, Integration, KBArticle

```

## Operational invariants (read before writing code)

- **Never `where: { id }` without `tenantId`.** Use `req.scoped.configurationItem.findFirst({ where:{ id }})` — `withScopedDb` injects `tenantId` automatically. Raw `prisma.*` bypasses scope.
- **`publicId` is what URLs show.** `GET /api/v1/cmdb/:publicId` → repo maps `publicId → id`. Keep `@unique publicId` on Event/Incident/Problem/Change/Release/Deployment/ServiceRequest/KBArticle/MonitoringRule/AlertRoute/CI.
- **`Division.code` etc. are tenant-unique, not global.** `@@unique[tenantId,code]` → same code can exist in different tenants.
- **`ApplicationTeam.role` defaults `CONTRIBUTOR` (`202`).** `OWNER` required to edit team-app link.
- **Session has no FK to Tenant.** `Session.tenantId String` is denormalized; `resolveSession` joins `Session.userId→User→TenantMembership` to validate.
